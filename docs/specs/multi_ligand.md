# 多配體同時對接 → MD：幾何、排除、力場與報告（D-60）

使用者（11/02 17:48）：多重分子同時對接時版型與圖表要調整；進入 MD 要特別小心穿模與不合理構型；
同時對接時要能排除並智慧調整（例如改一下姿勢，或判斷哪一個是不合理的對接把它排除）；力場也很複雜。請全力思考。

## 一、問題從哪裡來
1. **Vina 看不到的東西。** Vina 只用重原子與極性氫打分，沒有靜電項，排斥是軟的。建模時才補上非極性氫，
   所以對接時「剛好不碰」的姿勢，加氫後可能重疊。
2. **穿環（ring piercing，穿模）。** 一個分子的鍵穿過另一個分子的環：配體穿配體、配體的鍵穿過 Phe/Tyr/Trp/His/Pro 的環、
   蛋白的鍵穿過配體的環。能量最小化**解不開**：鍵被環卡住，不是爆掉（NaN），就是在不可能存在的拓撲下繼續模擬。這是最危險的一種，因為後者不會報錯。
3. **漂浮配體。** 聯合姿勢中某配體不碰蛋白也不碰其他配體，MD 中會直接漂走，對「共同佔位」沒有意義。
4. **一深一淺。** 一個配體埋在口袋、另一個只靠在第一個身上（已有規則：每個配體接觸 ≥ 10，D-早期）。
5. **同號電荷。** 兩個同號帶電的配體在一起，Vina 不會懲罰，MD 會互斥（已有 note，報告新增 caution）。

## 二、檢查（`md20/build/multi_ligand.py`，純 numpy、單位 Å）
| 檢查 | 判定 | 理由 |
|---|---|---|
| 穿環 | 另一分子的鍵與環平面相交且交點在環多邊形內 | 幾何定義；環由鍵圖找最小環（3–8 員），鍵由共價半徑＋0.45 Å 推定或用拓撲 |
| 重疊 | 重原子–重原子 < 2.2 Å、重原子–H < 1.3 Å、H–H < 1.0 Å（跨分子；金屬略過） | 氫鍵 H···受體 ≥ 1.5 Å、供體···受體 ≥ 2.5 Å，真實接觸不會被誤判 |
| 漂浮 | 4 Å 內蛋白重原子 < 3 且 4.5 Å 內沒有其他配體 | 不與任何東西作用 |

## 三、處置順序（寧可擋也不要猜，但能證明安全的就自動做）
1. **自動改選聯合姿勢**（只在 simultaneous、使用者沒有指定 `pose_choices.joint` 時）：在**已通過對接規則**的其他名次中，
   依 cluster 大小、再依分數，找第一個幾何可進入 MD 的。所有系統（含單配體系統）改用該名次。AUTO_FIXED，寫入決策日誌。
2. **剛體微調**（`relieve`）：只動有問題的配體，旋轉 ≤ 30°、平移 ≤ 2 Å，從最小位移開始試（6000 組，固定亂數種子可重現）；
   接受條件：該配體所有重疊與穿環消失、保留 ≥ 70 % 蛋白接觸、RMSD ≤ 2.0 Å（同一結合模式）。微調後的姿勢另存 `multi_ligand/<名>_nudged.sdf`，只用於多配體系統。
3. **漂浮配體自動移出多配體系統**（AUTO_FIXED）：它在此姿勢沒有作用，留著只會漂走並污染分析。剩下 < 2 個配體時不另建 docked_multi。
4. **其餘 → NEEDS_HUMAN，並指名要排除誰**：牽涉問題最多的配體（穿環權重 10、重疊 1、漂浮 5），平手時選蛋白接觸較少者（較不可信的姿勢）。
   選項（GUI 一鍵）：`multi_ligand.exclude: [X]`（建議）、`pose_choices: joint=<名次>`、`multi_ligand.accept_geometry: true`（不建議，報告標註）。

被否決的做法：
- **自動排除碰撞的元兇**：排除配體改變了科學問題（「這幾個成分能否同時結合」），屬使用者決定；系統只負責指名與給理由。漂浮配體例外，因為它本來就沒有參與結合。
- **讓最小化自己推開**：重疊時配體常被推出口袋；穿環時根本推不開。
- **軟核（soft-core）最小化或重新柔性對接**：效果較好但需要額外的 alchemical 力場或重跑 Vina，成本高，列為未來選項。

## 四、三道關卡
| 關卡 | 位置 | 看什麼 |
|---|---|---|
| 姿勢層 | `Workflow._multi_geometry`（`_cases_to_build` 建 docked_multi 前；simultaneous 與 independent 兩種來源都做，取代舊的 2.5 Å 重疊檢查） | 對接姿勢 SDF＋對接受體 10 Å 內殘基 |
| 建模層 | `assemble._geometry_backstop`（每個系統，加完所有氫、溶劑化前） | 全部原子含氫；可微調時直接改 modeller 座標（AUTO_FIXED），否則 NEEDS_HUMAN |
| 最小化後 | `engine.runner._minimize` 讀 `minimize_final.pdb` | 只查穿環（重疊已被最小化消掉，穿環不會）；有 → NeedsHuman，不進入加熱 |
最小化後的蛋白檢查以殘基為單位（側鏈環），跨殘基的主鏈鍵穿過配體環未涵蓋（罕見，列為未決）。

## 五、力場
- **同一系統統一力場與電荷模型**（`assemble._consistent_ladders`）：若配體各自落在 OpenFF Sage（NAGL 電荷）與 GAFF2（AM1-BCC）等不同組合，
  依序嘗試讓全部改用 Sage、再全部改用 GAFF2，且電荷方法一致；成功 → AUTO_FIXED；做不到 → advisory，報告標註。
  理由：同一口袋中配體之間的作用若來自兩套參數，比較時無法歸因。取捨：個別配體可能不是其最佳選項。
- 殘基名 L01、L02…不重複，模板產生器以分子圖比對，同一分子出現兩次不衝突。
- 1-4 縮放（0.5／0.8333）Amber、GAFF2、Sage 相同，不需處理。
- **限制（寫進報告「限制與注意事項」）**：固定電荷、配體之間沒有極化；Vina 無靜電項；平底限制讓配體不會完全離開，因此「共同佔位維持」需無限制重跑確認。
- 已有：多配體系統每個配體質心對口袋 Cα 質心加平底限制 ±0.4 nm（結合自由能步驟關閉）；advisor 對 simultaneous 建議 gentle 約束、教學等級 20 ns、搜尋強度 32。

## 六、報告版型（同時對接）
對接一節改以「排列」為主角，不再每個配體各畫一套（版面不隨配體數倍增）：
姿勢分數 → 聯合姿勢相似度（座標串接）→ 漏斗（有參考時）→ **F38 共同佔位檢查** → **F39 各配體位置**（顏色＝配體，偵測互換位置）→
**F40 子位點地圖** → 姿勢表（接觸數按配體分列＋配體間最短距離欄）→ **幾何檢查表**（蛋白接觸、重疊、穿環、漂浮、處置）。
MD 一節多配體系統加 **F41 配體之間的距離**（有平底限制時加 caution）。用語見 `report_language.md`。

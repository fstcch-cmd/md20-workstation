# Spec: MD20 的寫作風格與四種語言（D-74）

使用者回饋（2026-11-03）：介面、報告與學生文件「太有 AI 感」，常見的 AI 斷句與符號一看就知道不是人寫的。
本檔是改寫與之後新增文字的規範。對象是學生與老師：一位實驗室的老師在旁邊口頭說明的語氣。

## 1. 要避免的寫法（四種語言共通）
- 用破折號（——、—、–）連接兩個子句或插入說明。改成兩句，或用逗號、句號。表格裡表示「沒有值」的單一「—」可以保留。
- 一句話裡用冒號帶出另一段話（「結論：……；理由：……」）、分號串好幾個子句。標籤後面的冒號（「狀態：」）可以保留。
- 括號一個接一個塞補充說明。只留真正必要的（單位、縮寫第一次出現的全名）。
- 「／」或「/」當成「或」「和」使用。寫出「或」「和」。
- 箭頭「→」寫在句子裡代替動詞。流程步驟的標題列可以保留。
- 公式化的開場與收尾：「值得注意的是」「需要注意的是」「總而言之」「此外」「旨在」「確保」「關鍵在於」「不是……而是……」
  （英文："It's worth noting", "crucial", "ensure", "seamless", "robust", "leverage", "delve", "In summary", "not X but Y" 句型）。
- 為了湊成三項而列三項；每句都加粗；每段都用同樣的句型開頭。
- 過度修飾或過度保證的語氣。只講事實、數字與該做的事。

## 2. 要的寫法
- 短句、主動、具體。先說要做什麼，再說為什麼。
- 數字、門檻、單位、科學判斷**一字不改**（例如 2 Å、kT、0.005 nm ps⁻¹、ΔG° 不輸出的條件）。改的是說法，不是內容。
- 同一個概念全專案用同一個詞（見 §4 詞彙表）。
- 介面上的按鈕與標籤用名詞或動詞短語，不加句號。

## 3. 程式中的多語文字
- 共用工具：`md20/i18n.py`（`LANGS`、`LANG_NAMES`、`pick()`、`cjk()`、`colon()`、`paren()`、`stop()`）。`advisor.tx` 就是 `pick`。
- 文字以固定順序的 tuple 寫在使用它的程式旁：`(zh, en, ja, ko)`。舊的 `(zh, en)` 仍可讀（日文、韓文退回英文），但
  `tests/test_i18n_coverage.py` 會要求全部改成四種語言。
- 函式形式同樣依序加參數或關鍵字：`_(zh, en, ja, ko)`、`F(level, zh, en, ja, ko)`、`P(zh, en, ..., ja=, ko=)` 等。
- `if lang == "zh": … else: …` 這類二選一，改成四種語言（tuple 加 `pick`，或 `cjk(lang)` 決定標點）。
- f-string 的佔位符、`.format` 的欄位名、HTML 標籤、程式識別字（參數鍵、閘門名、檔名）**不翻譯、不改**。
- 標點：中文與日文用全形（，。：（）「」）；韓文與英文用半形標點。
- DecisionLog 的 `why` 依專案規則維持中文；報告中以原文顯示。命令列（`md20/cli.py`）維持中文。

## 5. 學生文件
`docs/students/` 有四種語言：`WINDOWS.md`、`MAC.md`（繁中）與 `WINDOWS.en.md`、`WINDOWS.ja.md`、`WINDOWS.ko.md`、`MAC.en.md`、`MAC.ja.md`、`MAC.ko.md`。
指令、路徑、檔名、數字在各語言版本完全相同。

## 6. 驗證
- `tests/test_i18n_coverage.py`：程式中沒有只剩兩種語言的文字（`tools/i18n_scan.py` 為 0）。
- `tools/gui_preview.py`（CI `gui-preview`）：四種語言各頁截圖；計算進行中切換四種語言、離開再回來、再按開始，計算必須只啟動一次、持續進行、只有一個流程。

## 7. 未決
- 日文與韓文由開發者撰寫，尚未經母語者校對；收到校對意見時記在本檔。
- 仍為中文：DecisionLog 的理由、命令列輸出、`drivers.py`、`platforms.py`、`winfix.py` 產生的診斷文字（電腦狀態頁會以中文顯示這幾行）。

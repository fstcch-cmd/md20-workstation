# Spec: LLM 編排與智慧化輔助（D-161）

狀態：草案，待使用者與其他模型審查。此檔定義「把 LLM 串進 MD20」的架構、邊界與規範。
範圍修正：2026-10-31（`04` 文件）曾把「AI 模型連接器」移出範圍。本規格**正式更正**：LLM 編排納入範圍，但嚴格分層——有界的專家迴圈對外，核心僅限內部。更正的理由與授權見 DECISIONS D-161。

目標：讓 MD20 表現得像裡面住了一位生物資訊專家——使用者用白話描述想解決的問題，系統就把結構整理對、策略選對、失敗診斷對、報告寫對。引擎是商品（OpenMM 等），**這個整合的專家迴圈才是差異化，也是護城河的互補**。

---

## 0. 北極星願景（終極目標）

讓一個**完全不懂分子模擬、但有想發展的專案**的外行人，用他自己的口語、**任何語言**，透過 LLM 對話，LLM 就自動接管整個程式，在前中後深度參與，產出專案報告。終極目標：**用說的、用任何語言說的，就能完成完整的分子模擬。**

這個願景逼出四條設計真相，是本規格所有護欄的理由，不能為了「更好用」而讓步：

1. **教學版是通往它的正確路徑**。博士生是「能檢查」的使用者；先在能檢查的人身上把專家迴圈驗證到可信，才開放給「不能檢查」的外行人。誠實閘門、證據層級、報告規範是為外行人版鋪的地基，不是教學版的裝飾。
2. **外行人無法判斷科學對錯，所以閘門與誠實報告是最重要的部分**。唯一擋在外行人與「自信但錯誤的科學」之間的，就是閘門、寧可擋也不猜、證據層級。最該防的失敗：一份漂亮自信的報告讓外行人過度相信（例：告訴做發酵的人「你的萃取液有抗發炎功效」）。降低門檻，但不降低真相。
3. **「自動接管」＝在既有有界自主框架（`autonomy.md`，D-137/143）內的自動化**，不是「LLM 想做什麼就做什麼」。閘門、預算、帳本、不可逆決定一樣停下升級。差別：外行人那端沒有專家能解 NEEDS_HUMAN，所以 LLM 要嘛在界內自行解例行閘門，要嘛用外行人聽得懂的白話解釋處境並給選項，真需要專業判斷時誠實說「這需要專家」。不能把外行人卡在他看不懂的閘門前。
4. **「完整」的界線要先講好**。能：外行人用說的跑出完整、正確的模擬，拿到誠實的「這告訴你什麼、不告訴你什麼」。不能：模擬不會定論他真實世界的問題。交付給外行人的是**誠實假說 + 需要哪些濕實驗驗證**，不是「電腦說我的萃取液能抗發炎」。這已足夠有價值：讓研究者知道該先做哪個濕實驗。

本規格以下各節（有界表面、閘門權威、報告誠實、授權分級、檔案紀律）都是為了安全抵達這個北極星而存在。

## 1. 五條不可違反的原則（所有實作都要守）

1. **LLM 叙述，MD20 執行**：LLM 是專家的腦（要做什麼、為什麼），MD20 是驗證過的手（用已測試的工具正確、確定性地做）。LLM 不自己做科學，不逐位元手改資料。
2. **閘門是最終權威**：三態閘門（PASS／AUTO_FIXED／NEEDS_HUMAN）照舊由確定性邏輯判定。LLM 只能「提議」config 或選一個合法選項，**永遠無法把閘門直接設成 PASS**。它改的是輸入（世界），閘門這個裁判不變。
3. **寧可擋也不猜**：LLM 不得為了「讓流程繼續」而降低科學標準硬闖。做不到時，最專業的輸出是「這做不到，原因是…，你真正的選項是…」。
4. **核心不外露**：end-user 層的 LLM 只接觸「有界表面」（問題、證據、config schema、能力清單、使用者的科學檔案、報告）。引擎原始碼、演算法、參數化邏輯、閘門判定邏輯、驗證/授權內部，永不進入這個表面。
5. **可重現的是產物，不是對話**：LLM 是隨機的。可重現的是它產出的 `config.json` 與改好的檔案（都有 SHA、進 DecisionLog）。從產物重跑是確定的；對話不是紀錄。

## 2. 三階段價值：前、中、後

LLM 的價值貫穿一個案例的前、中、後，三段各有明確的職責與邊界。

### 2.1 前——意圖拆解與排序
使用者用白話描述想解決的問題（例：「我想知道這個萃取液裡的代謝物有沒有抗發炎潛力」）。LLM 讀 `capabilities.json` 與四階段流程，把白話**拆解並排序**成可執行的計畫：

- 選模式：單一 docking／**高通量篩選（HTS）**／胜肽等。發酵萃取液「有哪些潛在功效」這類問題，一開始就該推 HTS 模式。
- 補齊要素：建議受體（例：NF-κB p65）、配體來源、分析方法、自由能層級（MM/GBSA 排名 → PMF 機制 → alchemical 定量，知道何時用哪個）。
- 產出一份 `config.json` 草案 + 一段「為什麼這樣設」的說明，交使用者確認。

邊界：LLM 產出的是**提議的 config**，不是直接開跑。消費級/弱模型的提議一律經 schema 驗證。

### 2.2 中——錯誤診斷與指揮修改（真正的智慧化）
當 docking／MD／傘狀採樣出現問題（NaN、建模閘門擋下、約束/凍結的需求、對接失敗），LLM 介入診斷並指揮 MD20 調整：

- MCP 丟給 LLM 的是**結構化問題**：`{階段, 中文理由, 證據（數字）, 一組有限的合法選項}`（三態閘門本來就輸出這些）。
- LLM 用**受限動作**回應：`propose_config_change(key, value)`（限制在 `DECISION_KEYS`／config schema、有範圍驗證）、`select_gate_option(gate, option)`。沒有 `edit_code`、沒有引擎檔案存取。
- MD20 拿新 config **重新讓閘門判定**。例：MD 爆 NaN → LLM 提議「前 100 ps 凍結主鏈 + 對殘基 X 加平底約束 k=…」→ 重跑 → 閘門重判穩定度。LLM 動的是旋鈕，碰不到積分器。
- 每個補救進 DecisionLog（誰=LLM、改了什麼、理由）；科學性改動標記待人工複核。
- **升級**：若診斷出「這不是 config 問題，是引擎少了某能力」，LLM 不自己硬解，而是產生一個開發任務，交回內部 developer 層（見 §6、§10）。

### 2.3 後——客製化專案報告
分子模擬結束後，LLM 把**使用者原本想解決的情境**與 MD20 的報告結合，產出客製化的專案報告。詳細規範見 §8。

## 3. 有界表面 vs 護城河

| 層 | 內容 | end-user 層 LLM | developer 層 LLM |
|---|---|---|---|
| **資料層**（安全側） | 使用者的 PDB/配體/軌跡/config/報告/log、結構化問題與證據、能力清單、config schema | ✓ 讀/診斷/提議修改（經驗證與閘門） | ✓ |
| **核心層**（護城河） | 引擎原始碼、演算法、參數化、閘門判定邏輯、驗證/授權內部 | ✗ 完全不暴露 | ✓ 僅限內部 source build + developer 授權 + 本地模型（§6） |

重點：一個生資專家修 PDB，不需要讀你的溶劑化演算法。所以「專家級的強大」和「核心不外露」是不同層，可同時成立。邊界由「殼暴露什麼」來守（§7 的工作目錄 scope）。

## 4. 規則檔：每次連線都交給 LLM 的「憲法 + 除錯手冊」

一份版控在 repo 的單一 markdown（`docs/llm/MD20_LLM_GUIDE.md`，本檔的同類是你們的 `CLAUDE.md`），作為 MCP `instructions` 欄位的來源，每次任何 LLM 連進來就交給它。單一真相、可審查、可改版。分 end-user 版與 developer 版。

內容五塊：
1. **角色**：MD20 的編排/診斷助手，指揮已測試的工具，不自己做科學。
2. **硬規則**：§1 的五條原則，逐條白話。
3. **能力地圖**：指向 `capabilities.json`、四階段、可用工具。
4. **除錯步驟手冊（step-by-step）**：遇到閘門/錯誤 → 讀結構化問題 + 證據 → 對應到有限選項或一個 config 旋鈕 → 驗證 → 重跑 → 重判；何時升級為開發任務；常見故障→補救樣式（NaN→質子化/碰撞/盒子/約束；docking 失敗→搜尋框/受體 prep…）。
5. **報告誠實與寫作規範**：證據層級；**嚴格遵守 `docs/specs/writing_style.md`**（不要 AI 腔與符號，見 §8）。

規則寫得越明確，弱模型/本地模型越不會脫稿；版控讓你隨「發現模型常犯什麼錯」持續修它。

## 5. 串接架構：一個核心、很多薄轉接頭

LLM 串接方式會持續爆炸（MCP client、各種 bot、程式內直登）。**不要窮舉，要解耦**：把「操作層」和「協定層」拆開。

- **操作核心（只做一份）**：MD20 的工具 + 閘門 + 規則檔 + 決策記錄。所有邏輯、護欄、授權分級都在這裡。
- **薄轉接頭（一種串接=一個薄殼）**：
  1. **MCP 轉接頭**：給 Claude Desktop 等 MCP 客戶端（主要路徑）。
  2. **程式內 BYO-key 面板**：使用者在 MD20 的 GUI 直接登入他的 LLM（填 API key 或本地端點 URL）。用**相容 OpenAI 格式**的端點，一套同時吃 OpenAI、Claude（走其 API）、Ollama/vLLM 的本地模型。
  3. **REST/JSON API**：給不會講 MCP 的 bot（Grok 等）：一個穩定、文件化的 HTTP 介面。

三個轉接頭都是同一核心、同一規則檔、同一組閘門的薄殼。未來新串接=再加一個薄轉接頭，核心不動。

跨所有轉接頭必須一致：
1. **護欄一致**：任何轉接頭拿到的閘門、規則、決策記錄都一樣。任何轉接頭都不能是繞過閘門的後門。
2. **BYO-key 安全**：見 §5.1。
3. **授權分級一致**：license tier 決定每個轉接頭暴露哪些操作。

### 5.1 三條登入路徑（先澄清：聊天訂閱 ≠ API 金鑰）
消費者的聊天訂閱（ChatGPT Plus、Claude Pro）**不等於** API 金鑰；API 另外計費。所以「用訂閱的 LLM 登入」有三條不同的路：

- **路徑 A — 用現有訂閱、MD20 不碰金鑰（最省事、最安全的「用訂閱」）**：走外部客戶端 + MCP（§5 的轉接頭 1）。使用者用已付費的 Claude Desktop／ChatGPT app 當驅動，連到 MD20 的 MCP server。MD20 不經手金鑰。
- **路徑 B — 程式內面板 + API key**：需要 API 金鑰（＝另外的 API 計費，不是聊天訂閱）。金鑰進作業系統憑證庫、遮罩、風險同意閘（§5.2）、預算上限。適合想把一切留在 MD20 GUI。
- **路徑 C — 本地模型（最簡單、最安全，推薦給外行人與敏感資料）**：Ollama／LM Studio，只填 `http://localhost:11434` 之類網址，沒有金鑰、沒有費用、資料不出門。最契合北極星（外行人用說的就能做）與未發表結構。

程式內面板 UX：一個**供應商選單**（OpenAI／Anthropic／Google／本地 Ollama／自訂 OpenAI 相容），選了就預填端點與需要的那一格（金鑰或網址），使用者只填一格。供應商支援 OAuth「用帳號登入」就提供；但 OpenAI/Anthropic 的 API 目前多為金鑰制。預設引導：外行人→路徑 C；要用現有訂閱→路徑 A；願意開 API 計費→路徑 B。

**金鑰儲存**：只存本機作業系統憑證庫（Windows Credential Manager／macOS Keychain），永不進 repo/log/明文設定、不上傳、只送往使用者指定的端點；可隨時撤銷。走外部客戶端（路徑 A）時金鑰留在使用者的 app，MD20 根本不經手。

### 5.2 連接前的風險告知與同意閘
第一次連某供應商的 API 之前，用白話告知風險、取得明確同意、記時間戳（同「資料夾存取同意」模式）。沒同意就不連。要揭露的風險：
1. **金鑰外洩**：金鑰只存本機憑證庫，不上傳、不進 log（見 §5.1）。
2. **資料外送（雲端模型）**：用雲端模型時結構與問題會送到該供應商。**敏感/未發表資料不要用雲端，改用本地模型（路徑 C）。**
3. **不當調用/費用**：API 按量計費；失控的工具呼叫迴圈會燒錢。設**用量/預算上限**，超過就停、要使用者確認。
4. **提示注入**：LLM 處理不信任的內容（下載的 PDB、惡意檔名）可能被操弄；LLM 的動作一律經驗證與閘門。

同意逐供應商一次性記錄；撤銷金鑰或切換供應商時重新告知。

## 6. 授權分級、兩種 build、本地模型

- **license 是存取控制，不是護城河本身**。授權的 `tier` 加 `developer`／`internal` 級（或 `features:[core_dev]` 旗標），用既有 RSA-PSS 簽章驗證（只有擁有者能簽），通過才解鎖更深的工具。
- **真正的護城河是兩種 build**（配合 D-128 編譯/加密發行層）：
  - **出貨 build（end-user）**：核心編譯/加密，原始碼不在裡面；只跑有界 MCP，連「碰核心的工具」都不存在。任何 license（甚至偷來的）都解不開不存在的東西。
  - **內部 source build**：核心原始碼在（你的 repo），`developer` 授權才解鎖「LLM 碰核心」的工具。
- **碰核心的 LLM 一定用本地模型**：雲端 LLM 要「幫你改核心」就得把原始碼送到第三方 API，等於把護城河寄出去。所以 end-user 有界輔助可雲端或本地；**內部碰核心的開發輔助一律本地模型（千問等）**，核心留在你機器上。

## 7. 檔案存取與診斷

使用者產出的科學檔案是**資料**，不是核心，所以 LLM 讀/修它們落在安全側。

### 7.1 怎麼把檔案給 LLM（三種，預設用結構化診斷）
1. **結構化診斷（預設）**：MD20 先用自己已測試的分析（結構 QA 閘門已在算：缺失 loop、altloc、Ramachandran 離群、clash score、SEQRES 對帳、HETATM 清單、是否加氫、解析度）產出精簡診斷交給 LLM。小、可靠、讓 LLM 專注在判斷層而非 parsing。
2. **按需讀原始片段**：`read_file(path, 選取)` 只回傳需要的切片（某段 SEQRES、某殘基原子、自訂配體連結），不是整檔。
3. **整檔上傳（少數、明確）**：只有小檔或使用者明確要才整個給。大軌跡永遠只給算好的分析。

### 7.2 「修好再丟回去」的紀律
LLM 不直接寫位元組進資料。它的修是兩種：
- **(a) 指揮 MD20 的 prep 工具**：「補 loop 45–52、pH 7.4 質子化、刪 5Å 外的水」→ MD20 用 PDBFixer/pdb2pqr 執行。
- **(b) 少數要手改**（如修壞掉的自訂配體連結）：LLM 提議內容 → **MD20 先驗證**（能否 parse、過合理性檢查）→ 才寫。

共同鐵則：**永不覆寫原始檔**，一律寫新版本（`3PTB_fixed_v2.pdb`），可回溯；進 DecisionLog；修好的檔**重新進管線、再過閘門**。

### 7.3 Scope（邊界由殼暴露什麼來守）
檔案工具只開在使用者的**專案/案例工作目錄**，不開安裝好的 md20 套件、引擎原始碼、系統路徑。這條 scope 讓「伸手捞檔案」不會滑成「伸手捞核心」。

## 8. 報告寫作（後）：LLM 怎麼參與

### 8.1 兩種形式，一份文件
- **預設報告（canonical）**：MD20 既有的確定性報告（圖、解釋模板、閘門；見 `figures.md`、`report_language.md`）。永遠存在、可重現、不需 LLM。數字、圖、方法都在這裡，是正典。
- **LLM 客製版**：LLM 讀 (a) 使用者原本想解決的情境、(b) 預設報告的結構化結果，寫出客製化敘述，**整合進同一份報告**（不是另開一份斷掉的文件）。

### 8.2 LLM 能動與不能動的（有限度）
LLM 只寫入報告指定的「敘述槽」：
- **可寫**：執行摘要、把結果放回使用者領域脈絡的討論（例：對發酵/功能性食品的意義）、下一步建議。
- **不可動**：方法、結果數字、圖——那些由 MD20 機器產生，是正典。LLM 不得改任何數字或圖。
- **證據層級**：只給假說，不給已證實的功效。發酵/功效題目尤其要守——不能把「docking 分數不錯」寫成「有保健功效」。
- **透明**：客製版清楚標示哪些段落是 LLM 寫的、哪些是機器產生的（透明 + 可重現）。

### 8.3 寫作風格：不要太有 AI 感
報告（與所有 LLM 產出的文字）**必須遵守 `docs/specs/writing_style.md`（D-74）**。語氣是「實驗室老師在旁邊口頭說明」，不是聊天機器人。規則檔要把這份風格規範明確交給 LLM，重點包括：

- 不用破折號（——、—、–）串子句；改兩句或用逗號句號。
- 不用冒號帶出另一段、不用分號串一堆子句。
- 不用「／」當「或/和」；寫出「或」「和」。
- 不用箭頭「→」在句中代替動詞。
- 不用公式化開收尾：「值得注意的是」「總而言之」「此外」「不是…而是…」（英文 "It's worth noting", "crucial", "ensure", "seamless", "leverage", "delve", "In summary", "not X but Y"）。
- 不為湊三項而列三項、不每句加粗、不每段同句型開頭。
- 不用 emoji 與裝飾符號。只講事實、數字與該做的事。

---

## 9. 決策記錄與可重現
- LLM 的每個決定（前的 config、中的補救、後的報告敘述）都進 DecisionLog：誰=LLM、哪個模型、改了什麼、理由。
- 可重現的產物：`config.json`、改好的結構檔、客製報告的「敘述槽」內容，皆有 SHA。
- 從產物可完整重跑；對話僅供參考，不是紀錄。

---

## 10. 自我升級迴圈
end-user 的專家迴圈診斷出「核心少了某能力」→ 升級成開發任務 → 丟進內部 developer 層（source build + developer 授權 + 本地模型）→ 在那裡 LLM 幫開發者改引擎。於是對外的專家迴圈發現核心不足，對內的開發迴圈補上。**但核心修改仍進版控、過 CI、人工複審**——LLM 是強的初階工程師，不是繞過審查的後門。

---

## 11. 隱私
把使用者結構/資料上傳雲端 LLM，等於把研究資料送出機器。敏感資料（例：發酵題目未發表的結構）**應走本地模型**，在本機診斷、不出門。規則檔要讓系統在偵測到敏感資料時提示或強制本地模型。

## 12. 里程碑與未決

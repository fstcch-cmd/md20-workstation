# Spec: 自動產圖的規則（折線圖為主）— D-89

## 1. 問題（使用者 2026-11-04 09:50、09:52，附筆電截圖）
- 「標注蓋過圖本身」：氫鍵數圖的圖例放在圖內，六個配體的圖例壓在折線上。
- 「每個折線的意義不明、為什麼都是同一個顏色」：COM 距離與極性接觸的圖看起來有十幾條同色折線。
- 「折線圖的 label 不清、意義不明，要重新規劃整個繪圖的邏輯」。

## 2. 原因（查證）
1. **時間軸錯誤（主因）**：正式模擬分段存成多個 DCD。mdtraj 讀 DCD 時沒有時間資訊，每個檔都從 0 開始、每幀 1 ps。
   接起來後時間是 0–9 ps、0–9 ps……，於是**同一條**曲線每到一段結尾就畫回 x = 0。COM 距離圖的「十幾條同色線」其實只有一條，是 2 ns／10 段造成的折返；
   x 軸也只到 0.009 ns（應為 2 ns）。
2. 圖例放在圖內，系列一多就蓋住資料。
3. 系列名稱用拓撲殘基名（L01–L06），學生看不出是哪個化合物。
4. 每條線旁的點線（後半段平均）沒有出現在圖例，不知道代表什麼。

## 3. 規則（`md20/report/figures.py`、`md20/analysis/plots.py`）
1. **x 一定要遞增**：`time_axis()` 檢查；不遞增就改用「Saved frame（time axis not recorded）」並在軸標寫明，絕不把折返畫成時間。
2. **時間從模擬紀錄算**：`analysis/stream.production_times_ps()` = 總步數 × 時間步，平均分配到所有存檔幀（OpenMM 第一幀在一個間隔之後）；
   `load_production`、`export_centered`、膜分析與串流分析都改用它。舊專案的分析檔在產生報告時由 `_repair_times()` 依同一紀錄修正（不必重跑 MD；按「重新整理報告」即可）。
3. **圖例一律在圖的右側外面**：`legend_outside()` 在存檔前把每個子圖的圖例收成一欄放在右邊，圖本身大小不變（存檔用 `bbox_inches="tight"` 往右延伸），同名項目只列一次。
4. **每條線都有名字**：系列名稱用學生輸入的配體名，後面括號是拓撲殘基名，例如 `docked_multi PGA (L01)`。
5. **一個系列一個顏色，整份報告一致**：`series_style()` 依第一次出現的順序編號；超過 8 種顏色就換線型（實線、虛線、點虛線、點線）。
6. **最多 3 條疊在同一張圖**；超過就改成每個系列一個小圖（共用 x、y 軸），系列名稱寫在每個小圖左上角，用該系列的顏色。
7. **雜訊大的資料**：細線（半透明）是每個存檔幀，粗線是同色的移動平均（約 5 % 幀數），兩者都寫在圖例；不再畫沒有說明的點線。
8. 門檻線（例如配體 RMSD 3 Å）在圖例寫出數值。

## 4. 被否決的做法
- 圖例放在圖下方：系列多時會壓到 x 軸標或下一個子圖。
- 只靠顏色區分 6 條以上的線：顏色難以分辨、也不利色盲；改用小圖。
- 在報告產生時不修正舊的時間軸、要求重跑 MD：學生的 MD 可能跑了數小時，時間可以由紀錄準確重建。

## 5. 驗證
- `tests/test_figure_rules.py`：圖例移到圖外且不與資料區重疊（量測繪製後的邊界）；折返時間改用幀號；200 幀分兩段的時間是 10–2000 ps 且遞增；
  同一系列顏色固定、超過色盤換線型；筆電截圖的情形（6 配體、10 段）能產生圖。
- 以模擬資料產生兩張圖人工檢視（6 系列小圖、2 系列疊圖附門檻）。
- CI 的「報告範本」工作會用合成資料產生所有圖種。
- 未驗證：學生筆電上的舊專案按「重新整理報告」後的實際結果（需要使用者回報）。

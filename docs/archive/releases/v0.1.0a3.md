# MD20 v0.1.0a3: Windows and macOS installers (teaching preview)

MD20 runs docking, system building, OpenMM molecular dynamics, SMD and umbrella sampling on one computer.
This preview adds the new interface, the two teaching cases and the project-grade report.
The interface and the report open in English. Traditional Chinese is one click away in the language menu at the top right.

## Install on Windows (15–30 minutes, mostly downloading)
1. Download `MD20-Windows-v0.1.0a3.zip` below, right-click it and choose "Extract all".
2. In the extracted folder, double-click `Install-MD20.cmd`.
   - If SmartScreen appears, choose "More info" and then "Run anyway". The script is not signed.
   - The program goes to `%LOCALAPPDATA%\MD20`. It takes about 6 GB, so keep at least 8 GB free. An earlier version is not deleted. It is moved to `_to_delete`.
   - With an NVIDIA driver MD20 uses the CUDA platform, otherwise OpenCL.
3. Double-click `MD20-GUI.cmd` on the desktop. The interface opens at http://127.0.0.1:8020 and is reachable from this computer only.

## Install on macOS (15–30 minutes)
1. Download `MD20-macOS-v0.1.0a3.zip` and double-click it in Downloads. You get the folder `MD20-v0.1.0a3`.
2. Open Terminal and run `bash ~/Downloads/MD20-v0.1.0a3/Install-MD20.command`.
3. Double-click `MD20-GUI.command` on the Desktop. The command line is `~/MD20/md20`, for example `~/MD20/md20 doctor`.
   Macs have no CUDA. MD20 uses OpenCL or the CPU, so use the classroom tier for class work.

Step-by-step student guides are in `docs/students/WINDOWS.md` and `docs/students/MAC.md`.

## What is new
- **Four modes on the home page**:
  - Teaching mode 1: several small molecules (NF-κB p65 paper).
  - Teaching mode 2: peptide (Keap1 paper).
  - Quick mode.
  - Professional mode.
- **Teaching pages** show the paper, the background, the learning objectives, the scientific checks the case demonstrates, what each step teaches, the parameters with their reasons, and discussion questions. One click starts the case.
- **Parameter suggestions for your case**, also in professional mode:
  - Each of the 34 parameters starts from a value suggested for your case and goal, with the reason.
  - Every change is checked at once and marked as an error, a warning or a note, with a one-click suggestion.
  - The run time is estimated from this computer's benchmark.
- **Screening**:
  - Example Excel table.
  - Clickable ranking chart.
  - Manual SDF upload when downloads are blocked, with strict file naming.
- **Confirmation before molecular dynamics** after the poses are chosen.
- **Peptide scientific checks** for cell penetration and for access to the binding site. Before docking MD20 compares the peptide size with the box. After docking it checks burial and the distance to the site. These are notices and never stop the run.
- **Chain breaks** can be capped with neutral ACE and NME groups.
- **Ligands that coordinate a metal** have an opt-in distance-restraint fallback. That ligand gets no binding free energy, and the report says so.
- **Salt** type and concentration are set explicitly. The cation can be sodium, potassium, lithium, rubidium or caesium, and the anion chloride, bromide, fluoride or iodide.
- **SMD window starts** come from relaxed-spring frames, with ringing diagnostics.
- **More docking figures**: pose similarity, score funnel, positions in the box, contact residues across poses and ligand comparison. A report template with synthetic data shows every figure kind (D-59).
- **Several ligands docked together** are checked before MD for ring piercing, overlap and floating ligands. A clean joint pose is chosen automatically. The repairs are a rigid nudge or a soft-core relaxation, or you can exclude a named ligand in one click (D-60, D-61).
- **Binding cooperativity** comes from a thermodynamic cycle with a closure test. While one ligand is pulled, the others are held bound (D-61).
- **Free-energy profile reliability** (D-62). The profile must cover the whole pulled distance. An earlier version could stop the curve where its solver lost precision and report the edge value as the well depth. That case now switches to WHAM or is marked not converged. The error-bar resampling starts from the main solution, so it finishes sooner. The timing is recorded in the report data.
- **Default pulling velocity 0.005 nm ps⁻¹** (was 0.01, D-63). The faster pull dissipated most of its work and left the window starting points in a disturbed pocket. SMD now takes about one minute longer.
- **Soft-core repair acceptance** (D-64). A relaxed ligand is accepted by its centroid shift and the contacts it keeps. RMSD is used only as a sanity cap.
- **Stable interface** (D-67). Switching language or leaving a page no longer restarts a run. Only one calculation runs at a time, and a banner leads back to it. Times are shown in local time. Project names with non-ASCII characters get a short code, so different names never share a folder. Use letters and digits.
- **You choose how much of the computer MD20 uses** (D-68). The resource menu at the top right has "Light: keep using the computer", "Balanced (default)" and "Full speed: computer idle", and the choice applies from the next step. It sets the MD threads and GPU share and Vina's `--cpu`. On Windows it also sets the priority and power class of the helper programs (D-70, D-72). Pick Light to write a report while MD20 runs.
- **Closing the MD20 window ends its calculations on Windows** (D-69). Vina no longer keeps running in the background. Start MD20 again and it resumes where it stopped.
- **macOS installer** (D-66): `Install-MD20.command`, tested in CI by a real install.
- **Teaching mode 1 docks at exhaustiveness 8 in class** (D-71). The paper's 32 is kept for the research tier, because 32 took more than three hours on a student laptop.
- **Vina on Windows 11 hybrid CPUs** (D-72). Vina is tagged for full performance, so Windows does not move it to the efficiency cores while the MD20 window is hidden. Every docking run records how many CPU threads it really used, in the decision log under `docking.run / cpu_use`.
- **Report** in English or Chinese. Every section explains what the step is and why it matters, and lists the parameters used next to the recommended ones. Figures and tables are numbered, and the interpretation is written from the run's own numbers. The report ends with a methods paragraph you can reuse, the limitations, a full parameter appendix and the decision log.

## Known limitations
- Time for the first real case (trypsin and benzamidine) on an RTX 4060 laptop: the classroom tier took 76.5 minutes (measured), and the teaching tier takes about 3 hours (estimate). Macs and computers without an NVIDIA GPU are slower, so use the classroom tier.
- The Vina thread fix (D-72) has not yet been confirmed on the laptop.
- CI checks the interface by rendering every page in both languages. Interactive use (clicks, uploads, a full run started from the interface) is confirmed on the laptop.
- Some older automatic explanations and the decision log are in Traditional Chinese. The English report shows them as recorded.
- One-dimensional centre-of-mass free-energy profiles strongly overestimate binding for buried ligands. For trypsin and benzamidine at the teaching tier on the laptop, the profile gave about −21 kcal/mol against about −6 kcal/mol measured. The report withholds ΔG° in these cases, so compare ligands by trend only. Orientation and conformation restraints are not implemented yet.
- Bonded zinc model: the mean bond-length deviation is close to the 0.3 Å tolerance. Treat metal-site results as qualitative.
- The 1D centre-of-mass ΔG° is an approximation, and the report labels it as one.

Full status is in `docs/STATUS.md`, and the decisions are in `docs/DECISIONS.md`.

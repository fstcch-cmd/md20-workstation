# 討論紀錄：MD20 Lite（2026-11-11 至 11-12）

session_016gcJzBMFygWvETdrK5aZY8。這份是使用者與開發 session 的討論摘要，依時間排列。決策本身在 `docs/DECISIONS.md` 的 D-181、D-182，規格在 `docs/specs/lite_edition.md`。這裡只記「誰說了什麼、為什麼這樣定」。

## 1. 起點（11-11 上午）
- **使用者**：目標是開發 MD20 Lite，問在 MD20 裡要怎麼做一個低配版。
- **開發者初步建議**：Lite 不另開分支，做成同一套程式碼裡的設定。低配機器的耗時主要看原子數，所以重點是把體系變小（口袋截取、隱式溶劑、小水盒、HMR 4 fs），不是砍功能。
- **使用者更正方向**：
  1. 以後問問題要給可以選的選項。
  2. Lite 是要交付給別人的。它存在的理由是為完整版導流：用完 Lite 會想接著用完整版。

## 2. 使用者在選項中選的五件事
| 問題 | 使用者的選擇 |
|---|---|
| 完整版程式碼怎麼和 Lite 分開 | 同一份源碼，打包時把完整版模組實際移除 |
| Lite 用什麼方式限制 | 限規模，流程完整 |
| 什麼時候提示升級 | 報告內附對照，加上碰到上限時提示，兩者都要 |
| 別人怎麼取得 Lite | 免費，但需使用者簽發的授權檔 |
| 要不要隱式溶劑快速預覽 | 提供，報告加註限制 |

## 4. 開發過程
- **使用者**：仔細思考後繼續開發流程，遇到問題自行解決。
- 開發者讀了 repo 後更正三件事：
  1. 決策編號已到 D-180，Lite 是 D-181，不是早上寫的 D-111。
  2. 授權不新增 `lite` 等級，改在既有的 `features` 欄位放 `lite` 這個字。新增等級要動授權格式與私人簽發端的測試向量。
  3. 隱式溶劑快速預覽只在有 GPU 時提供，而且不能做 PMF。既有規格（D-25）實測 GBn2 在純 CPU 上很慢，既有閘門也擋掉結合自由能。
- 開發者自己寫核心契約 `md20/edition.py`，再把四個工作包交給 Sonnet 子代理（high effort）：打包、流程、報告、介面。
- **使用者中途中斷**，問是否有發起 Sonnet 5.5 high 的子代理。開發者回答有，並說明啟動時選的是 sonnet 選項、無法從自己這邊確認實際版本。
- 報告與介面兩條子代理自己完成。流程與打包兩條被中斷時停止，程式與測試已寫完但未提交。使用者說「Keep going」後，開發者沒有重啟子代理，自己檢查測試、接手提交、補上 CI 工作與規格。
- 整合後容器全套 1,725 passed、50 skipped、0 failed。成果以 git bundle 放到使用者筆電的 `MD20-sandbox`。

## 5. 三個科學模組要不要拆
- 開發者回報：`sampling/adaptive.py`、`engine/longrun.py`、`analysis/extended.py` 被基本流程用到，無法從 Lite 移除，程式碼仍在 Lite 安裝包裡。給兩個選項：A 先不拆、搭配核心編譯出貨；B 現在就拆。
- **使用者**：你自行決定。
- **開發者選 A**（D-182）。理由：拆模組要用真實引擎重新驗證，而 Lite 連一次真機執行都還沒做；這三項已有入口檢查與流程內判斷兩層擋；之後要拆隨時可拆。
